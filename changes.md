# Changes from vanilla nchat

This is the customization inventory for [YeoBL/nchat](https://github.com/YeoBL/nchat),
on branch `codex/personal-features`.

Vanilla baseline: nchat **5.17.26**, upstream commit
[`ea41fd4`](https://github.com/d99kris/nchat/commit/ea41fd4), recorded locally and
on GitHub as the annotated `vanilla-base` tag.
[Compare the full customization](https://github.com/YeoBL/nchat/compare/vanilla-base...codex%2Fpersonal-features).
Newer upstream releases have not been silently merged into this baseline.

The older implementation existed as uncommitted changes. Its commits are a
**reconstructed logical feature history**, not recovered original dates. Shared
plumbing has separate prerequisite commits; closely related controls sometimes
share an implementation commit. Checks below describe the final integrated
build, not a claim that every reconstructed intermediate backend snapshot was
independently runnable. The widget snapshots were independently compiled.

Partial history does not overwrite current read/download state, reorder chats,
clear pending unread alerts, or initiate automatic paging/account metadata
requests. Previously uncached incoming history is locally non-notifying; this
does not mark it read on WhatsApp. Outgoing history does not gain an invented
read tick. Fresh unavailable-message resends retain normal unread handling.

WhatsApp still does not expose a complete historical per-person receipt/voter
query through this client. The native
[history request](https://github.com/tulir/whatsmeow/blob/main/send.go) returns
messages **before** its anchor, not including it. Missing phone history,
encryption secrets, hidden identities and pending-queue overflow can still leave
lists incomplete; restarting cannot recreate data that was never supplied.
The Channels regression sample is
[public upstream test data](https://github.com/beeper/argo-go/blob/v1.1.2/fulltest/file.argo),
not an export of this user's account. Operation mappings follow the bundled
[upstream query-ID inventory](https://github.com/tulir/whatsmeow/blob/089932318bc2cb833dba4176db44f78fccf05730/argo/name-to-queryids.json).

**This is not an all-working feature list.** Statuses below now include the UX
and bug-fix follow-up. The initial audit found real failures despite passing
baseline tests; those cases now have permanent regressions. Remaining service,
privacy and historical-data limits are still explicit. Tests do not establish
that every real WhatsApp/Telegram action or native device workflow succeeds.

### Faster everyday workflows

- **F3 → enter text → Enter** immediately searches all cached chats. **Filters
  (optional)**, **Edit search** and **Clear filters** stay above results; edit
  only the filter you need. Telegram server search follows the same text-first
  principle under **F2 → Account tools → Search Telegram history**.
- Ordinary forms show current/default values as individually editable rows.
  Optional values do not force a wizard; consequential actions still require
  explicit confirmation, with Cancel safely selected. Failed actions preserve
  entered values for retry. Long list excerpts are bounded; full previews stay
  complete.
- **Option-Shift-T** starts transcription without a modal wait. Close tools to continue chatting;
  use **F2 → Transcription status** for pending/completed/failed outcomes, or
  **Search saved audio transcripts** for saved text.
- **Option-O** preselects your recorded poll choices. Edit choices, then explicitly
  **Submit**; **Clear selection → Submit** withdraws where permitted. **Refresh**
  updates results/voters. Unconfirmed submissions never retry automatically.
