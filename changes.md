# Changes from vanilla nchat

This is the customization inventory for [YeoBL/nchat](https://github.com/YeoBL/nchat),
on branch `codex/personal-features`.

Vanilla baseline: nchat **5.17.26**, upstream commit
[`ea41fd4`](https://github.com/d99kris/nchat/commit/ea41fd4), recorded locally and
on GitHub as the annotated `vanilla-base` tag.
[Compare the full customization](https://github.com/YeoBL/nchat/compare/vanilla-base...codex%2Fpersonal-features).
Newer upstream releases have not been silently merged into this baseline.

The older implementation existed as uncommitted changes. Its commits are a
**reconstructed logical feature history**, not recovered original dates. Shared
plumbing has separate prerequisite commits; closely related controls sometimes
share an implementation commit. Checks below describe the final integrated
build, not a claim that every reconstructed intermediate backend snapshot was
independently runnable. The widget snapshots were independently compiled.

## Verification audit — 20 October 2026

Audited implementation: [`4a914f89`](https://github.com/YeoBL/nchat/commit/4a914f8930e89d7e8e5725e56c464bce047be479).
**This is not an all-working feature list.** Every inventory row now has an audit
status. Existing tests and the full build pass, but additional production-code
probes reproduced the failures below. No fixes, configuration changes, app
restarts or live account mutations were performed in this audit.

| Status | What it establishes |
|---|---|
| Offline verified | Relevant behavior exercised with synthetic data, production components and/or fake protocols. Not proof of a real service/device roundtrip. |
| Live unverified | Implementation and service dispatch exist; offline checks/source tracing do not prove the real send/read/download/upload or native-app interaction works. |
| Source reviewed | Conversion/rendering path inspected and compiled, without a direct runtime fixture for that feature. |
| Config-dependent | Source exists, but installed helpers, terminal configuration, permissions or native database compatibility determine behavior; interaction remains unverified. |
| Partial | Confirmed defect, incomplete implementation, missing UX or deployed-source mismatch; details in the row. Live effects can also be unverified. |
| Broken | A targeted offline reproduction produces an invalid request or fails the advertised workflow. |

### Confirmed problems and missing behavior

These are **unfixed at the audited revision**. D1/D2 are the most urgent because
they can lose a draft or terminate the client. Reproductions used isolated
synthetic messages/fake protocols, never real chat mutations.

### Audit execution and limits

The current macOS implementation was rebuilt successfully with
`cmake --build build -j6`. The notification, widget-reply and real-dialog UI
suites passed, as did current-source local drafts/search/tools/media tests,
Telegram parsing/pagination helpers and WhatsApp's 11 Go race tests.
Installed/build widget self-tests and hidden-window layout/animation checks
passed. Native recorder/transcriber signatures and synthetic conversion/encoding
checks passed; a fresh archive-test build was used rather than trusting an older
test executable.

**Passing baseline suites did not mean all features worked.** Additional
production-model/dialog probes reproduced D1, D2, D4 and D6; the actual WhatsApp
request builder reproduced D3. These isolated audit probes are not yet permanent
regression tests. D5/D7/D9 include source-confirmed omissions; D8 comes from
installed-file comparison and a no-write installer dry-run. Each feature's row
states whether evidence is runtime, source-only, configuration-dependent or
incomplete.

No live messages, votes, read receipts, story/status posts/views, membership/admin
changes, microphone/camera captures or Speech authorization were triggered.
Actual cross-device sync, remote downloads/uploads, native Preview/Quick Look,
clipboard/browser interaction and service completeness therefore remain
unverified where indicated. No app restart, helper replacement, behavior fix or
account-data modification was made.

Not claimed: complete inaccessible historical receipts/voters, phone Secret Chat
imports, externally opening timed/protected Secret Chat media, universal WhatsApp
view-once recovery, full official-client community/business parity, or voice/video
calls. Missing service data is shown as unavailable/partial, not fabricated.

Existing vanilla functions such as Shift-Tab previous chat, Ctrl-A/E line movement,
Ctrl-C clearing the textbox, basic mentions and ordinary file transport are not
misrepresented as new custom features.
